# UI/UX-аудит

Працює з власним ізольованим Chromium (не заважає Playwright MCP і паралельним агентам).

## 1. Підготовка
- Dev-сервер: `npm run dev` (Astro, http://localhost:4321/). Перевір `curl -s -o /dev/null -w "%{http_code}" http://localhost:4321/` — має бути 200. Якщо вже запущений — не запускай другий.
- Скріншоти й звіти пиши в scratchpad / тимчасову теку, **не в репозиторій**.

## 2. Автоматичні перевірки
```bash
node .claude/skills/ui-ux-audit/scripts/audit.mjs --url http://localhost:4321/ --out <тека> [--viewports mobile|tablet|desktop|all] [--full]
```
- `--viewports`: `mobile` (320, 360, 375, 390, 414), `tablet` (768, 834, 1024×768), `desktop` (1280, 1440, 1920), `all` (за замовчуванням). Можна комбінувати: `mobile,tablet`.
- `--full` — додатково повносторінкові скріншоти (важкі; для великих сторінок ріж на частини перед переглядом).
- Результат: `<тека>/report.json` + `<width>x<height>-top.png`.

Що означають поля `report.json` для кожного viewport:
| поле | що це | поріг |
|---|---|---|
| `docOverflow`, `overflow` | горизонтальна прокрутка / елементи за межами екрана (крім каруселей `[data-scroller]` і fixed) | має бути 0 |
| `brokenImages`, `imagesNoAlt`, `stretched` | биті, без alt, сплющені картинки | 0 |
| `smallTargets` | кнопки/посилання < 24px (`fail`) або < 44px на мобільних (`warn`) | fail = 0 |
| `lowContrast` | текст на суцільному фоні з контрастом < 4.5 (або < 3 для великого) | 0 |
| `unnamed` | кнопки/посилання без доступного імені | 0 |
| `headings` | кількість H1 і пропуски рівнів | 1 H1, без пропусків |
| `clippedText` | обрізаний текст без ellipsis | 0 |
| `consoleErrors`, `failedRequests` | помилки JS і запити 4xx/5xx | 0 |

Контраст на градієнтах/картинках скрипт не оцінює — перевір їх очима на скріншотах.

## 3. Візуальний огляд (обов'язково дивись скріншоти через Read)
Мінімум: 320, 390, 768, 1024, 1440, 1920. Для кожного перевір:
- **Сітка й вирівнювання**: однакові відступи між секціями, вирівняні краї карток, немає «сиріт» (одна картка в рядку), колонки не стискаються до нечитабельності.
- **Типографіка**: H1 не довший за 4–5 рядків на мобільному, немає висячих прийменників/одного слова в рядку в заголовках, довжина рядка тексту 45–80 символів на десктопі.
- **Ієрархія**: головна CTA помітна на першому екрані на кожному розширенні; другорядні дії не конкурують з нею.
- **Накладання**: липкі елементи (шапка, мобільна CTA, кнопка месенджерів, тост-сповіщення) не закривають контент, кнопки чи форму.
- **Узгодженість**: ті самі радіуси, тіні, кольори кнопок/чипів у всіх секціях; іконки одного стилю.
- **Стани**: hover/focus видимі (перевір фокус з клавіатури Tab), disabled-стрілки каруселей відрізняються.
- **Нейтральність палітри** (вимога замовника): не переважає ні рожевий, ні блакитний — сторінка має пасувати і хлопцям, і дівчатам.
- **Планшет 1024×768** — найчастіше ламається: перевір сітки lg-брейкпоінта.

## 4. Звіт
Поверни чеклист, відсортований за важливістю:
```
[P1|P2|P3] <розширення> · <секція> · <що не так> → <конкретна правка: файл/клас/значення>
```
P1 — ламає використання (не видно CTA, переповнення, нечитабельно); P2 — помітна вада якості; P3 — шліфування.
Не вигадуй проблем: кожен пункт має спиратися на скріншот або поле `report.json`.
